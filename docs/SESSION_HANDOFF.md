## 1. What it is
Academic Progression & Registration Intelligence System for DHA Suffa University (BS Software Engineering **SE**, BS Cyber Security **CYS**). Advisors upload a student's **Interim Transcript** + **Plan of Study Fulfillment Report** (PDFs); APRIS reads them (deterministic code, no AI), applies rules, recommends courses/sections with reasons, the advisor approves, and it exports an Excel/CSV for IT plus a combined PDF. Every action is audited (hash-chained). Stack: Next.js 16 (App Router, server actions) + TypeScript + Prisma/SQLite + Tailwind; pdfjs-dist, read/write-excel-file, pdf-lib, nodemailer. **Next 16 has breaking changes — check `node_modules/next/dist/docs/` before writing Next code.**

## 2. How to work on it
- Run: `cd apris && npm run dev` (http://localhost:3000). **Restart the dev server after any `prisma migrate`** (a stale server lacks new tables). Only one `next dev` per project folder.
- Checks: `npx tsc --noEmit && npx eslint && npx vitest run` (≈89 tests; ~10 skip when `data/sample/` PDFs are absent). CI (GitHub Actions) runs on `clean-main`.
- Dev logins `admin` / `hod` / `advisor`: passwords are in git-ignored `apris/.dev-credentials.txt` (`npm run dev:credentials` regenerates). **Never write passwords into chat.**
- Local DB `prisma/dev.db` (git-ignored). `npm run seed` = DEV-ONLY reset; production uses `seed:init`. `scripts/reset-fresh.ts --yes` wipes students/audit (keeps reference data).
- The auto-mode shell classifier sometimes fails transiently: retry once, then use `mcp__terminal__run_in_terminal` (one-line ASCII commands, no parentheses/`×`). Verify the server actually answers (`curl`) before saying it is running.
- **Privacy:** real student PDFs, gradebooks and extracted CSVs stay OUT of git (`data/sample/`, `storage/`, `Downloads`). Tests/docs use invented IDs only (the PRD example `SE251093` is fine). Scan staged diffs for real IDs before pushing.
